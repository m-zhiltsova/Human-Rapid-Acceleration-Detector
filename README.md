## Описание

**Speed Est** определяет реальную скорость ходьбы и бега людей по обычному монокулярному видео — без LiDAR, без стереокамеры, без датчика глубины. Это достигается за счёт объединения **предварительно вычисленной метрической карты глубины** пустой сцены (генерируется один раз с помощью Microsoft MoGe v2) с живым **многоцелевым трекингом** и **детекцией ключевых точек лодыжек**, а затем всё это пропускается через оценщик скорости на основе фильтра Калмана со скользящим окном.

```
Видео ──► YOLO v8 ──► ByteTrack ──► MoveNet лодыжка ──► Семпл глубины ──► Калман ──► км/ч
                                                               ▲
                                               Карта глубины MoGe (предвычислена)
```

> **Точность:** пайплайн рассчитан на неподвижные камеры наблюдения с чётко выраженной плоскостью земли. Качество падает при сильном дисторшне объектива или непланарной сцене.

## ✦ Возможности

| Компонент | Детали |
|---|---|
| **Детекция** | YOLOv8 ONNX — letterbox-препроцессинг, NMS, только класс «человек» |
| **Трекинг** | ByteTrack с appearance-based Re-ID (EMA HSV-гистограмм, косинусное расстояние) |
| **Ключевые точки** | MoveNet SinglePose Lightning — лодыжки, спроецированные обратно в координаты кадра |
| **Глубина** | Microsoft MoGe v2 Large — метрическая глубина по одному кадру, сохраняется по ID камеры |
| **Оценка скорости** | Фильтр Калмана в мировых координатах `[X, Z, Vx, Vz]` + скользящее окно 2 с + удаление выбросов IQR + EMA-сглаживание отображения |
| **Вывод** | Составное видео: аннотированный кадр камеры + 2D вид сверху с траекториями |
| **Фильтры** | Опциональные CLAHE, NLM-шумоподавление, нерезкое маскирование |

## ─── Быстрый старт ───────────────────────────────────────────────

### Шаг 1 — Сгенерировать карту глубины для камеры (один раз)

Сфотографируйте сцену **без людей** и запустите:

```bash
python src/depth_estimator.py \
    --input  путь/до/пустой_сцены.jpg \
    --camera_id  cam_001 \
    --device cuda
```

Будут созданы `cfg/cam_001/points_map.npy`, `mask.npy` и `meta.json`.

---

### Шаг 2 — Запустить пайплайн

```bash
python src/main.py \
    --empty_frame  путь/до/пустой_сцены.jpg \
    --video        input.mp4 \
    --camera_id    cam_001 \
    --det_model    models/yolov8n_best.onnx \
    --movenet_model models/movenet_singlepose_lightning_4.onnx \
    --output       result.mp4
```

Или запустить глубину и пайплайн одной командой:

```bash
python src/main.py \
    --empty_frame empty.jpg \
    --video input.mp4 \
    --camera_id cam_001 \
    --run_depth          # ← автоматически запустит depth_estimator.py
```

## ─── Трекер — ByteTrack + Appearance Re-ID ──────────────────────

Стандартный ByteTrack использует только IoU-сопоставление, что вызывает **смену ID при пересечении людей** (≈ 30–40 % траекторий в многолюдных сценах). В проекте добавлен **пост-проход Re-ID на основе внешности**:

```
Назначен новый ID трека
        │
        ▼
  Есть недавно потерянные треки в памяти?
        │  да
        ▼
  IoU перекрытие ≥ 0.10  И
  косинусное расстояние HSV-гистограмм ≤ 0.30?
        │  да
        ▼
  Восстановить старый ID  ← [ReID] frame 412: new ID 31 → restored as ID 7 (score=0.21)
```

Каждый трек хранит **EMA HSV-гистограмм** (кроп верхней части тела, 32 бина H + 32 бина S). Память внешности хранится **3 секунды** после исчезновения трека.

Пороги трекера также ужесточены по сравнению со стандартным ByteTrack:

| Параметр | Стандарт | Этот проект |
|---|---|---|
| `track_thresh` | 0.35 | **0.50** |
| `match_thresh` | 0.95 | **0.70** |
| `track_buffer` | 90 кадров | **45 кадров** |
| `min_box_area` | 5 пикс² | **400 пикс²** |

## ─── Оценка скорости — как это работает ────────────────────────

```
пиксель (cx, cy)
    │
    ▼
points_map[cy, cx]  →  мировые (X, Z) в метрах
    │
    ▼
KalmanFilter [X, Z, Vx, Vz]  (dt-адаптивный шум процесса)
    │
    ▼
скользящее окно  →  Δ расстояния / Δt по кадрам  →  список сырых скоростей
    │
    ▼
удаление выбросов IQR  →  медианная скорость
    │
    ▼
EMA-сглаживание  →  отображение км/ч  (обновляется каждые 2 секунды)
```

**Фильтры прыжков** применяются до подачи в Калман:
- Пропускаем кадр если прыжок пикселя > `max(30, ширина_bbox × 0.5)` пикс — ловит телепортацию от смены ID
- Пропускаем кадр если высота bbox изменилась более чем на 40 % — ловит скачки масштаба от ошибок трекинга

## ─── Формат вывода ───────────────────────────────────────────────

Выходное видео — горизонтальный композит:

```
┌─────────────────────────────────┬──────────────┐
│                                 │              │
│   кадр камеры                   │  2D вид      │
│   bbox, окрашенные по скорости  │  сверху      │
│   ID:3  12.5 км/ч               │  кам ↑       │
│                                 │  ○ ID:3      │
│                         1280 пикс│      320 пикс│
└─────────────────────────────────┴──────────────┘
```

Цвет bbox кодирует скорость линейно: **зелёный → красный** в диапазоне 0–15 км/ч.  
Панель 2D показывает полукруговые кольца расстояний каждые 5 м и траектории каждого человека.

## ─── Калибровка глубины ──────────────────────────────────────────

MoGe выдаёт относительную глубину. После запуска depth_estimator можно указать полиномиальную калибровку для перевода в метрический масштаб. Положите `calibration.json` в `cfg/<camera_id>/`:

```json
{
  "type": "polynomial",
  "coefficients": [0.0, 1.0, 0.0]
}
```

`coefficients` в порядке `numpy.poly1d` (старшая степень первая). Пайплайн применяет `K = poly(Z)` как попиксельный множитель масштаба к `points_map`.

## ─── Известные ограничения ──────────────────────────────────────

- Карта глубины должна быть сгенерирована с **точно того же положения камеры**, что и видео инференса — даже небольшой сдвиг или поворот даст неверные метрические координаты
- Точность скорости снижается при частичном перекрытии людей или на краях карты глубины, где качество MoGe ниже
- Детекция лодыжек MoveNet работает хорошо на расстоянии до ~15 м от камеры; дальше кроп bbox слишком мал и используется эвристика
- Пайплайн не поддерживает fisheye и широкоугольные объективы без предварительного устранения дисторсии
